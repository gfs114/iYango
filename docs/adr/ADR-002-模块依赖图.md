# ADR-002：七模块单向依赖图与端口绑定位置

- 状态：已采纳（P0 起生效，P2 扩展）

## 决策

```
app ──► feature:main ──► core:domain ──► core:model
 ││        └──► core:designsystem ──┘
 ├──► data ──► core:domain / core:model
 └──► platform:android（P3+ 学校客户端等）
```

- `core:model`、`core:domain` 为纯 JVM 模块，禁止依赖任何 Android 类型；
- `feature:main` 只依赖领域端口与设计系统，**禁止依赖 data/Room**；
- `data` 实现领域端口（Room/DataStore/JSON），不反向依赖 feature；
- 所有 Hilt 端口绑定集中在 `app/di/AppBindings.kt`（实施方案 5.1）；
- 版本目录 `gradle/libs.versions.toml` 为唯一依赖事实来源，禁用动态版本。

## 关键场景裁决

- W9 导入导出：data 层服务（W5）不能被 feature 直引 → 在 core:domain 定义
  `ScheduleTransferPort`（预览/提交用不透明 token 衔接），data 层做外观实现。
- 默认作息（恢复默认 11 节）：常量放 core:domain `ScheduleDefaults`，因为
  feature 不允许依赖 data 的 DemoSeeder。
- 跨包共享枚举（`CourseDeleteScope`）放 feature:main 的 schedule 包并被
  coursedetail/today 复用，不升级到 core（纯 UI 语义）。

## 后果

- 编译期即阻止跨层泄漏（已验证：feature 无 `com.gfs.iyango.data` import，
  core 无 `android.*` import）；
- 端口新增（saveSemester/saveTimeSlots/duplicate/ScheduleTransfer/ThemeSettings）
  均先改 core:domain 再由 data 实现，保持单向。
