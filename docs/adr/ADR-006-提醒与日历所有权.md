# ADR-006：提醒与系统日历的所有权

- 状态：已采纳（为 P5 预先定界）

## 决策

1. **规划与执行分离**：`CourseReminderPlanner`（core:domain）从
   `ResolveScheduleOccurrences` 产出提醒计划；平台层（通知/闹钟、系统日历）
   完全重写，不移植 ArkTS 平台代码。
2. **实例身份锚点 = occurrenceId**：提醒与日历事件的去重/更新键即
   `CourseOccurrence.occurrenceId`（见 ADR-003：调课不改身份，取消=压制）。
3. **谁创建谁删除（所有权）**：由导入/替换/同步路径触发的计划重建，必须
   在同一事务完成后追加重算（W5 在 ImportScheduleService.commit 的 KDoc
   已预留 P5 挂点）；用户手动创建的日历事件（非本 App 签名）不得删除。
4. **双通道**：本地通知（闹钟精确触发，厂商电源策略兜底）+ 系统日历
   （可选写日历，默认关闭）；通道各自维护事件 id 映射，互不串扰。
5. **无 GMS 依赖**：提醒能力不依赖 Google 服务（实施方案运行环境约束）。
6. 时间缺失（timeUnconfirmed / minute=null）的课不生成定时提醒，
   展示为"时间待定"，禁止套默认作息。

## 后果

- P2 的 occurrenceId 规则即 P5 契约雏形，接入提醒时无需迁移身份；
- 替换导入/课表删除后提醒重算有明确挂点，避免孤儿提醒。
