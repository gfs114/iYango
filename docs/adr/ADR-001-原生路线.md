# ADR-001：原生 Android（Kotlin + Compose）路线

- 状态：已采纳（P0 起生效）
- 决策日期：2026-10（P0）

## 背景

iYango 已有 HarmonyOS ArkTS 实现（参考仓 ClassSchedule-exp）。Android 版需要同一套课程规则服务今日页、周课表、冲突检查、提醒、日历与桌面组件，并处理学校会话失效、Cookie 轮换、后台恢复与厂商电源策略。

## 决策

采用原生 Android：Kotlin + Jetpack Compose + Coroutines/Flow + Hilt + Room。
不把 ArkTS 逐文件翻译为 Kotlin，而是按职责与数据契约重建：课程规则/发生模型作为纯 Kotlin 领域层移植（与参考逐字段对齐语义），UI 按 ui-baseline 契约重绘。

## 备选与放弃理由

| 备选 | 放弃理由 |
|---|---|
| Flutter / Compose Multiplatform 共享 | 桌面组件、精确提醒、日历、原生登录仍需插件/原生桥接；近期无 iOS 需求 |
| WebView 包装 / PWA | 离线规则、精确提醒、桌面组件、大屏交互均需大量额外实现 |
| 逐文件翻译 ArkTS | ArkUI/AppStorage/RDB/Want 等概念无对应物，机械翻译产生错位职责 |

## 后果

- 正面：能力间桥接层最少；问题可直接追踪到 Android 实际状态；核心功能不依赖 GMS。
- 负面：领域规则需人工移植并逐条对齐语义（已用 103+ 单测锁定）；UI 不能直接复用参考代码。
