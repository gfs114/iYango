# ADR-005：刷新与并发规则

- 状态：已采纳（P1 定型，P3 扩展）

## 决策

1. **Room 是唯一事实来源与单写路径**：页面不持有业务缓存，全部经 DAO Flow
   （InvalidationTracker 自动重发）；`refresh` 在 P2 语义 = 触发本地重算/重放，
   不发网络。
2. **同任务并发合并**：同一账号、同一任务、同一条件的进行中操作共享结果
   （实施方案 §6），防止连续下拉创建多条查询链；等待锁有超时，
   等待被取消不得释放他人持有的锁。
3. **优先级**：主动登录/导入 > 安静的前台刷新（启动/回前台统一刷新信号）。
4. **导入/批量写**：单 `db.withTransaction`，失败整体回滚（W5 导入、
   W9 duplicate 均如此）；导入会话 token（文件摘要）在提交后即失效。
5. **应用层双保险先于数据库约束**：唯一性等约束先由 Validator 拦截
   （可读错误文案），DB 索引兜底。
6. UI 用不可变 UiState 区分：首次加载/刷新中/空/有数据/失败保留旧数据/
   需要登录/权限未授予，不用单一 isLoading。

## 后果

- P2 的 30s 心跳（课表页/今日页）只驱动状态重算，不产生新数据链；
- 并发错误集中在端口实现层，页面无锁概念。
