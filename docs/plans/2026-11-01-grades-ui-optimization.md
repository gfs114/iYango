# iYango 成绩页 UI 优化详细修改方案

> 实施代理：沿用用户指定的 GPT 6.1 Sol 编写代码、主代理独立审查。开始实施时使用 subagent-driven-development 或 executing-plans，按本文任务逐项完成并记录证据。

**Goal：** 缩短从进入成绩页到查看课程、选择课程、查看计算结果的操作路径，让自选算分结果在浏览长列表时仍可见。

**Architecture：** 沿用 `GradesViewModel → GradesUiState → GradesPageLayout`，复用现有成绩计算器、查询协调器、缓存分区及选择上下文。主要调整页面组合、组件位置和展示状态；计算栏通过现有 `GlassScaffold.bottomBar` 固定，正文继续滚入玻璃顶栏后方。

**Tech Stack：** Kotlin、Jetpack Compose、Material 3、现有 Backdrop 玻璃设计系统、StateFlow、Compose UI / Robolectric 测试、Gradle 离线 Debug 构建。

**日期：** 2026-11-01（Asia/Shanghai）。

**文档状态：** 设计及实施计划，尚未执行代码修改。本文的尺寸、排布和交互是待实现方案；仓库现状另有标注。本文不表示已经通过新一轮测试、构建或真机验收。

## 2. 已核实的现状与问题

### 2.1 当前页面结构

源码：`G:/code/Android/iYango/feature/main/src/main/kotlin/com/gfs/iyango/feature/main/grades/GradesScreen.kt`。

```text
固定玻璃顶栏：成绩 / 脱敏账号与登录状态
└─ 单个 LazyColumn
   ├─ 学期标题 + 横向学期标签
   ├─ 排序标题 + 三个排序标签
   ├─ 筛选变更提示 + 查询按钮
   ├─ 登录、错误、未读更新、选择变更提示（按条件出现）
   ├─ 统计卡
   │  ├─ 自选入口，或已选数量及全选/清空/退出
   │  ├─ 加权平均 / 平均绩点 / 学分
   │  ├─ 纳入、排除说明
   │  ├─ 包含选修开关
   │  └─ 完整计算规则
   ├─ 缓存时间、查询范围与状态
   └─ 课程卡片列表
固定主导航：由根页面管理
```

### 2.2 源码层面确认的问题

| 现状 | 用户影响 | 本轮处理 |
|---|---|---|
| 自选工具及结果是 `LazyColumn` 普通条目 | 滚到列表后部必须返回顶部查看结果或退出 | P1 |
| 学期、排序、查询分多行常驻筛选卡 | 看课程前要经过较多控件 | P2 |
| 学期通过横向滚动标签展示 | 学期较多时选项不容易一次发现 | P2 |
| 统计卡完整规则始终展开 | 常用数字的视觉重点被分散 | P3 |
| 课程名及元信息均 `maxLines = 1` | 长标题、长学期与考试属性容易被截断 | P4 |
| 选择模式主要靠复选框区分 | 列表快速扫读时选中反馈不够明显 | P4 |
| 学期草稿与实际展示范围分离 | 改版若只突出草稿，容易误认当前成绩所属学期 | P2 必须明确标记 |

以上为源码结构判断，不等同于测得当前手机首屏高度、帧率或实际阅读速度。实施前用本地合成数据建立同尺寸对比图，不把未测量的数据写成优化百分比。

### 2.3 现有业务能力应完整保留

- 查询使用 `confirmAndQuery()`，下拉刷新使用 `refresh()`。
- `draftRange` 是待查询范围；`confirmedRange` 才对应当前缓存与成绩。
- 排序仅改变显示顺序，包含选修开关仅影响本地统计。
- 自选以记录 `id` 区分，`GradeSelectionContext(accountKey, range, revision)` 校验回调归属。
- 同名、同课程号、同稳定键的不同成绩行可以独立选中。
- 排序、修改草稿、标记已读、刷新失败保留选择。
- 账号变化、确认到不同范围、新快照替换会清空选择。
- 同一范围重新查询不在点击瞬间清空选择；成功替换快照后再清空。
- 登录过期仍可查看缓存并进行本地自选统计。
- 新快照为空时退出选择模式，并显示“已更新成绩，请重新选择”等现有适用提示。

## 4. 方案选择与推荐页面结构

### 4.1 三种布局方案的比较

| 方案 | 优点 | 代价 | 选择 |
|---|---|---|---|
| A：仅压缩当前统计卡 | 改动最少 | 滚动后仍看不到自选结果 | 不作为最终方案 |
| B：自选时固定底部计算栏，普通统计随列表滚动 | 选课反馈就近可见，普通浏览占用少 | 需处理底栏高度及小屏布局 | **采用** |
| C：把全部筛选与统计都固定在顶部 | 所有控件随时可用 | 固定区域过高，挤压课程列表与玻璃顶栏 | 不采用 |

### 4.2 普通模式结构

```text
┌─────────────────────────────────────────┐
│ 成绩                                    │ 固定玻璃顶栏
│ 脱敏账号 · 已连接教务                    │
├─────────────────────────────────────────┤
│ [学期 2026-2027-1 ▾]           [查询]    │ 随正文滚动
│ （仅草稿与已显示范围不同才提示）        │
│ 登录/错误/更新提示：沿用现有条件        │
│ ┌─────────────────────────────────────┐ │
│ │ 成绩统计             [自选算分]    │ │
│ │ 加权平均    平均绩点    统计学分    │ │
│ │   —           —          —        │ │
│ │ 纳入 N 条 · 排除 M 条              │ │
│ │ 包含选修 [开关]     [统计说明]     │ │
│ └─────────────────────────────────────┘ │
│ 更新于… · 当前实际显示的学期           │
│ 课程记录 N 条           [学校顺序 ▾]   │
│ 课程卡片……                             │
├─────────────────────────────────────────┤
│             现有主导航                  │
└─────────────────────────────────────────┘
```

图中 `—` 为无值示意；有数据时使用真实本地计算结果。第一阶段不重新设计缓存与异常文案，线框中的位置表示信息层级。

### 4.3 自选模式结构

```text
固定顶栏：继续显示“成绩”和账号状态
可滚动区：
  紧凑学期筛选
  现有适用提示
  简短自选提示：“勾选课程，下方实时计算”
  缓存信息
  课程记录 N 条                       [排序 ▾]
  [✓] 课程 A        学分 / 属性           成绩
  [ ] 课程 B        学分 / 属性           成绩
  ……
固定计算栏：
  已选 N 条                  [全选] [清空] [退出]
  加权平均          平均绩点          统计学分
    —                 —                 —
  纳入 X 条 · 排除 Y 条
  包含选修 [开关]                        [说明]
根页面主导航：保持原有位置与操作
```

- 自选模式不同时保留顶部大统计卡，避免两份结果及重复控件。
- 保留统计卡条目的稳定 key，在同一条目中替换为简短提示，降低列表位置跳动。
- 从顶部进入自选时不自动跳到底部、不滚回列表起点。
- 退出选择恢复普通统计卡；尽量保留当前可见课程及其滚动位置，不主动执行 `scrollToItem(0)`。

## 5. P1：固定自选计算栏

### 5.1 显示条件与职责

显示条件：有账号、`selectionMode == true`、存在成绩记录、当前成绩页处于活动状态。

计算栏负责展示结果和转发操作，不自行查询、不存储第二份选择集合、不重算学校绩点。

退出选择后移除栏及其额外底部占位。切换到其他主标签时不展示计算栏、不截获返回；返回成绩标签后恢复仍有效的选择状态。

### 5.2 内容及操作

| 内容/操作 | 行为 |
|---|---|
| 已选 N 条 | 当前快照内有效选中记录数；使用“条”，不误称独立课程门数 |
| 全选 | 选中当前已确认范围的全部有效记录 ID，不只选屏幕可见项 |
| 清空 | 清空选择，保持自选模式，不退出 |
| 退出 | 调用现有退出方法，清空选择并恢复正常详情点击 |
| 包含选修 | 复用现有 `includeOptional`，实时重新计算，保留勾选集合 |
| 说明 | 打开第 7 节统计说明面板，关闭后保留模式与选择 |

全选、清空、退出保持可见文字。窄屏换行，不依赖横向滑动才能找到退出。操作最小触控范围 48dp；清空在无选择时可禁用，全选在全部有效记录已选时可禁用，但不能由此禁用退出。

### 5.3 未选择与被排除的区别

| 状态 | 均分 | 绩点 | 统计学分 | 提示 |
|---|---|---|---|---|
| 已选 0 条 | — | — | — | 请选择课程 |
| 已选非空，但所有记录均被排除 | — | — | 0 | 已选 N 条，纳入 0 条、排除 N 条 |
| 有数值成绩及有效学分，全部缺学校绩点 | 正常显示 | — | 正常显示 | 说明中解释 GPA 分母 |
| 部分有学校绩点 | 正常显示 | 仅计算有绩点记录 | 正常显示 | 不自行补绩点 |

“统计学分”在普通和自选模式统一命名，说明中定义为被计算器纳入记录的学分总和。此项仅修正文案，不把它称为毕业已获学分或学校认定总学分。

### 5.4 位置、测量与底部空间

使用现有 `GlassScaffold.bottomBar`，不把栏放入 `LazyColumn`，不新增页面级全屏遮罩。

根页面已经传入 `bottomPadding`：

- 底部导航布局：`DockHeight + navigationBars + DockBreathing`。
- 侧边导航布局：`navigationBars + DockBreathing`。

成绩页不能再次追加 `navigationBarsPadding()`，也不能把默认 96dp 当成所有设备的导航高度。

布局契约：

```text
外部底部避让 = 页面参数 bottomPadding
计算栏容器下边距 = 外部底部避让 + 8dp
计算栏容器左右边距 = 16dp
选择模式列表底部内边距 = max(bottomPadding, innerPadding.bottom) + 16dp
普通模式列表底部内边距 = bottomPadding + 16dp
```

`innerPadding.bottom` 使用 Scaffold 对实际 bottomBar 的测量值，包含计算栏本身与容器下边距，不再手动重复加一次栏高。

列表仍铺满视口，用 `contentPadding` 避让；不将整张列表通过外部 `padding(innerPadding)` 缩到顶栏下方。

需要验证：滚到最后一条后，其课程名、复选框、分数与点击区域均能完全停在计算栏上方；切换系统导航模式、横竖屏和字体后仍成立。

### 5.5 小屏与大字号

默认布局为“操作行、指标行、摘要、设置行”，高度由内容测量，不写死 120dp 等固定高度。

- 可用内容宽度不足 360dp，或字体缩放达到 1.5 倍：已选数量与操作分行；操作允许换行。
- 指标保留三项；标签可换行。极窄宽度下用两列后换行，不缩小字体挤进一行。
- 极矮窗口/横屏/2 倍字体：计算栏内容高度上限取扣除顶栏及根导航后可用高度的 40%；栏内部允许纵向滚动，保留课程列表的主要操作区域。
- 该极端布局下保证“计算栏持续存在、每个操作可到达”，不承诺所有结果和按钮同时露出。
- 容器上下不硬裁剪内容，退出可通过栏内操作或系统返回完成。

### 5.6 玻璃、触摸及动画

- 第一轮固定栏使用现有 `GlassSurface` 的 `CONTENT` 材质，圆角 20dp；与统计卡保持同一套主题和降级行为。
- 该材质按当前实现采样全局背景，不宣称已经实现与主导航完全相同的正文折射。主方案不扩展共享采样 API。
- 栏位于 Scaffold bottomBar 层，不录入成绩正文采样层，避免自采样。
- 实体栏区域吸收空白处点击，不能点击到后面的课程；下方用于避让主导航的透明空间不能拦截主导航手势。
- 第一轮采用直接切换和现有控件反馈，不额外做整个长列表的高度动画、逐行进场、数字滚动或震动反馈。
- 选中课程只改变边框/背景及复选框，不增加每一行的折射层。

## 6. P2：紧凑学期选择与排序

### 6.1 筛选行

普通宽度显示：左侧可伸缩“学期 + 当前草稿标签 + 展开图标”，右侧“查询”。

标题长时，学期标签允许最多两行；查询按钮保持可达。窄屏或大字号必要时查询移到下一行右侧，不强行压缩为难点的小按钮。

排序不再放入筛选卡。移到课程列表标题行：“课程记录 N 条” + 当前排序菜单。

### 6.2 选择学期面板

使用 Material 3 `ModalBottomSheet` 与现有主题，不新增第三方弹层库。

内容从上到下：

1. 标题“选择学期”。
2. 说明“选择后点击查询更新成绩”。
3. “全部学期”。
4. 学校返回的学期列表，保持原始显示顺序。
5. 如果当前草稿或实际显示范围不在学校列表中，补充相应缓存项，明确标注“本机缓存”；同一值只显示一次。

学校项的 `value` 原样传入现有回调；不按当前日期推算、不拼接学年、不允许自由输入。

缓存补充项只是原有范围的展示回退，不借此遍历数据库构造新的可在线查询学期目录。与学校项同值时优先使用学校标签。

面板为单选列表，每行最小 48dp，带 radio 语义，当前草稿标为选中；实际显示范围可附“正在显示”，但不能同时表现为两个选中项。

### 6.3 点击与查询时序

```text
打开学期面板
  → 点击某学期
  → selectDraftRange(value)
  → 关闭面板
  → 页面仍展示 confirmedRange 对应成绩
  → 若 draftRange != confirmedRange，显示待查询提示
  → 用户点击查询
  → confirmAndQuery()
  → 进入现有缓存订阅及网络查询流程
```

- 点击面板外部、下滑关闭或按返回，不选择就不修改草稿。
- 选择后直接关闭，不再加一个功能重复的“确定”按钮。
- 点击已选学期也关闭面板，不发请求；草稿与实际范围相同则不显示“待查询”。
- 待查询文案：“待查询：{草稿标签}；当前显示：{确认标签}”。允许换行。
- 是否显示待查询提示用 `draftRange != confirmedRange` 判断，不只依赖现有 `rangeTouched`。后者还参与默认范围选择，不能为 UI 简化随意删除。
- 查询按钮沿用 `loggedIn && !querying` 可用条件；相同范围仍允许主动重新查询。
- 查询中禁用学期入口及查询按钮，已打开面板关闭，避免提交竞争。
- 面板打开本身不触发 `listTerms()`、不刷新成绩。

### 6.4 学期加载失败或缓存回退

- `loadingTerms` 为真：面板显示“正在获取学校学期”，保留可解释的全部/当前缓存项；不新增全屏阻塞加载。
- 列表为空且有已显示缓存范围：显示该缓存范围；不能呈现成“该学期没有成绩”。
- 列表为空且没有缓存范围：保留“全部学期”和解释“暂未取得学校学期列表”。
- 登录过期：仍允许打开面板了解范围；查询按钮不可用，沿用现有重新登录入口。不能承诺在此模式下新增跨分区离线切换能力。
- 学期数据异步到达时按 value 稳定标识，避免清空当前草稿或突然选中列表第一项。

### 6.5 排序菜单

| 菜单文案 | 传入枚举 | 含义 |
|---|---|---|
| 学校顺序 | `GradeSort.SCHOOL_ORDER` | 原始行顺序 |
| 分数从高到低 | `GradeSort.SCORE_DESC` | 沿用计算器可解析成绩与原有并列顺序 |
| 学分从高到低 | `GradeSort.CREDIT_DESC` | 学分降序，并列时保持原规则 |

入口可用短标签“学校顺序”“分数 ↓”“学分 ↓”，展开后给完整文案及勾选标识。

排序立即在本地生效，不显示“点查询生效”，不发网络请求，不清空选中记录，不自动退出自选。无成绩时隐藏列表标题与排序入口。

## 7. P3：统计卡及统计说明

### 7.1 普通统计卡

- 标题“成绩统计”，右侧文字按钮“自选算分”；无有效可选 ID 时入口不可用。
- 三项指标使用同一数字字重和对齐方式，不用三种高饱和色互相争抢注意力。
- 标签：“加权平均”“平均绩点”“统计学分”。
- 数字建议使用 `headlineSmall`，窄屏依据可用宽度换行；不通过限制系统字号保证排版。
- 数字下方保留“纳入 N 条 · 排除 M 条”。
- 设置行保留“包含选修”开关，右侧“统计说明”入口；必要时换行。
- 完整口径移入说明面板，不能删除。

### 7.2 统计说明面板的完整内容

标题：“统计说明”。

首先显示“仅供本地参考，以学校公布结果为准”，然后说明：

1. **当前范围**：普通模式为当前已显示范围全部记录；自选模式为该范围内勾选记录。草稿学期尚未查询时不参与计算。
2. **加权平均**：`Σ(数值成绩 × 学分) / Σ纳入学分`。
3. **平均绩点**：`Σ(学校返回绩点 × 学分) / Σ有学校绩点的纳入记录学分`；只使用学校返回值，不按分数转换。
4. **纳入条件**：学分大于 0，且具有数值成绩或现有解析器能解析出数值；关闭包含选修时，再排除属性包含“选修”的记录。
5. **文本成绩**：纯“优秀”“合格”等无数值原文不参与；现有解析器可处理“优秀（95）”这类包含数值的成绩，不能把它描述为所有文本均被排除。
6. **缺失绩点**：不影响该条记录参与加权平均，但该条不进入平均绩点的分子或分母。
7. **重复记录**：补考、重修及同名课程按各条记录计算，不自动合并、不仅取最高分。
8. **统计学分**：纳入上述计算记录的学分和，不表示毕业进度或已获学分。

面板支持纵向滚动，系统返回只关闭面板，不能顺便退出自选。关闭后恢复触发入口焦点；不会重置包含选修设置。

### 7.3 计算共享与格式

计算结果在页面公共父层只计算一次，再交给普通统计卡或固定计算栏。保持现有 `remember(records, includeOptional, selectionMode, selectedRecordIds)` 等价的失效条件。

不在每张课程卡或每次滚动回调中重新遍历所有记录。显示格式继续使用现有两位均分/绩点与整数或一位小数学分格式，不顺手改成不同精度。

## 8. P4：课程卡片结构与选中状态

### 8.1 常规信息层级

```text
[选择框，仅自选模式] 课程名称，最多两行          成绩
                    学期（仅全部学期范围）      绩点
                    2 学分  [必修] [学校考试性质]
                    原成绩 80 → 85（有变化时）
```

- 卡片内边距沿用约 14dp，卡片间距维持 10dp，圆角沿用 16dp。
- 名称使用现有 `titleMedium` 与半粗字重，最多两行，最终省略的全名仍可在普通详情查看。
- “新”“更新”标识移入可换行的辅助信息区域，避免挤占课程名的第一行。
- 学期在“全部学期”范围单独展示；具体学期下不重复显示。
- 学分、课程属性、考试性质采用可换行布局；不再用一个长字符串强制一行。
- 属性与考试性质优先原样显示，不自造“补考通过”“已获学分”等推断标签。
- 分数原文不裁成误导性的纯数字；空值为“—”。绩点缺失时不显示“0.00”。

### 8.2 长分数与窄屏策略

- 默认右侧分数区域最多占内容可用宽度的约三分之一，保留左侧标题空间。
- 分数原文超过两行可用长度时，或可用宽度小于 360dp/字体达到 1.5 倍，转为上下布局：课程名在上，成绩与绩点在独立下行。
- 不只根据设备名称判断，使用组件实际可用宽度与字体缩放。
- 学分和属性允许换行，不通过把字号降到不可读水平解决空间不足。
- 正常模式整卡点开详情；选择模式整卡切换一次选择，不同时弹详情。

### 8.3 选中视觉与可访问性

- 使用复选框 + 主题强调色细边框 + 淡色背景共同表达选中。
- 色彩不能是唯一依据，TalkBack 能读出选中/未选中。
- 继续采用父行 `toggleable(role = Role.Checkbox)`，内部复选框 `onCheckedChange = null`，避免一次点击两次切换。
- 不用 `GlassSurface.tintColor` 直接制作淡色选中态：该参数会影响默认前景色，且当前实现有较强着色。优先在现有外壳上加轻量边框与内部淡色背景，保持主题文字色。
- 选中纯文本成绩仍合法，显示已选但被统计规则排除；不要擅自禁用这类复选框。
- 每行稳定 key 继续使用 `record.id`，排序后选中态必须跟随 ID，不跟随屏幕位置。

## 9. 状态、弹层与生命周期约束

### 9.1 状态归属

| 状态 | 归属 | 保存策略 |
|---|---|---|
| 成绩、范围、选择 ID、选择版本、排序、包含选修 | 现有 ViewModel | 沿用当前生命周期 |
| 学期面板/统计说明/排序菜单是否打开 | 页面局部 Compose 状态 | 不写数据库，切到非活动页后关闭 |
| 列表滚动位置 | 一个共享 `LazyListState` | 普通/自选模式共用，不随模式重建 |
| 统计结果 | 页面派生值 | 随输入失效，不持久化 |
| 固定栏测量高度 | Scaffold 布局 | 不写 ViewModel，不固定常量 |

新增弹层建议统一枚举，避免两个面板同时出现：

```kotlin
internal enum class GradesOverlay { TERM_PICKER, STATISTICS_INFO, SORT_MENU }
```

以 nullable 当前 overlay 表示关闭。开启新浮层前替换旧值，不能叠放学期面板与统计说明。

### 9.2 返回与关闭优先级

1. 有 ModalBottomSheet 或菜单时，先由浮层处理返回并关闭。
2. 没有浮层且处于自选模式，返回退出选择。
3. 普通模式交回原导航行为。

页面自选 `BackHandler` 的启用条件为：当前主标签活动、选择模式成立、没有当前弹层。不能让一次返回既关面板又退出选择。

### 9.3 保留与失效矩阵

| 事件 | 选择 | 浮层 | 列表 |
|---|---|---|---|
| 排序变化 | 保留 | 关闭排序菜单 | 不强制回顶部，ID 稳定 |
| 学期草稿变化 | 保留 | 关闭学期面板 | 仍显示确认范围 |
| 确认到不同范围 | 现有逻辑清空并退出 | 关闭 | 不显示旧范围成绩 |
| 确认相同范围 | 请求发起时保留 | 关闭 | 保留当前记录，按现有缓存流程更新 |
| 新快照替换 | 清空；有记录时可继续处于选择模式 | 关闭以避免旧说明/回调 | 显示新快照与重选提示 |
| 刷新失败 | 保留 | 不强制改变无关浮层 | 保留缓存 |
| 账号切换/注销 | 清空并退出 | 关闭 | 防止旧账号信息残留 |
| 同账号登录过期 | 保留 | 保留仍合法的本地说明，学期查询不可执行 | 可继续本地统计 |
| 切换主标签 | 保留 | 关闭 | 保留滚动位置 |
| 新结果为空 | 退出 | 关闭 | 展示现有空态，不留下计算栏 |
| 标记已读 | 保留 | 保持 | 不误认为课程快照变化 |

所有选择回调继续带渲染时的 `GradeSelectionContext`，由 ViewModel 验证。不要为了“按钮一直可点”在点击时拿新上下文套用旧界面的记录 ID。

新学期面板的选择回调还需检查打开时账号与已确认范围仍属于当前页面；查询开始或账号/范围变化后关闭面板并拒绝旧事件。未改变账号和范围的学期列表加载完成不应无故关面板。

## 10. 布局、可访问性及性能标准

### 10.1 页面与共享组件约束

- `GlassTopBar` 继续固定，状态栏安全区仍由顶栏负责。
- 正文滚动视口从页面顶部开始，初始内容使用内边距避让，滚动后仍能进入顶栏后方。
- 根主导航、底栏液滴交互、课表页及其他主页面不改变。
- 第一阶段不修改共享 `GlassScaffold`、`GlassSurface`、玻璃材质参数与全局导航高度。
- 统计卡、固定栏、课程卡使用当前主题语义颜色；深色、浅色、壁纸和基础玻璃降级模式都需可读。

### 10.2 触摸及辅助功能

- 按钮、学期选项、排序项最小触控范围 48dp；视觉图标可以较小。
- 面板标题有明确语义，关闭后可恢复到原入口。
- 勾选课程后可读出该记录状态；结果区域可提供温和的汇总语义，不把每个数字设为独立强制播报，避免全选后连续打断。
- 缺失值朗读为“暂无数据”等明确含义，不只朗读横杠。
- 课程完整名称保留在语义或详情中；色盲用户可以通过勾选框与文字判断。
- 普通模式、选择模式、弹层模式均没有不可达的退出路径。

### 10.3 性能要求

- 开关面板、排序、选中、清空、进入退出自选都不发学校请求。
- 同一帧不重复执行整份统计与排序；用稳定输入进行记忆，滚动不触发统计重算。
- 保留 LazyColumn 按需组合，不能把所有成绩改成普通 Column 一次性生成。
- 不在 Composable 中做数据库读取、文件读取、HTML 解析或耗时日志。
- 使用稳定条目 key；固定栏与数字更新不得重建整个页面或重设滚动位置。
- 100/500 条合成数据可用于行为与局部性能观察；无真机帧数据时不写“稳定 120fps”“彻底无卡顿”等结论。

## 15. 后续可选项的具体设计（不属于本轮主方案）

### 15.1 P5：提示区整合

目标：把重复的在线/缓存说明降低为辅助信息，在需要动作时才突出提示。

拟定规则：

- 正常：仅一行“更新于 {时间} · {实际范围}”，不把登录状态“已连接”误写成实时网络在线。
- 登录过期：一条带“重新登录”的提示，清楚说明正在展示本地缓存。
- 查询失败但缓存存在：保留课程，提示失败原因与缓存保留；不把整个页面变为空态。
- 查询失败且无缓存：空态中给出明确重试/登录动作。
- 新增/更新：列表标题附近显示“新增/更新 N 条”，保留标记已读；不能把排序或进入页面视作自动已读。
- 选择因快照更新清空：保留独立原因提示，不被普通缓存时间覆盖。

需要额外核对：目前 `unreadCount` 的账号与分区统计范围、`message` 的显示路径；若没有完整证据，不改变未读统计语义。该项有独立测试与审查后再实施。

### 15.2 P6：详情底部面板

目标：让长课程名、成绩原文和属性更容易阅读。

拟定结构：

1. 拖动柄、完整课程名、关闭入口。
2. 较大成绩原文和学校绩点；缺失绩点显示“学校未提供”。
3. 学分与课程属性标签。
4. 学期、课程号、考试性质、原成绩等现有字段。
5. 新增/更新标识；仅在已有来源数据存在时展示。

约束：不添加模型里不存在的教师、分项成绩、排名；不再从别的学校参考代码中推断数据。

面板可滚动，最大高度不超过安全可用区域；返回只关闭详情。与统计说明/学期面板统一互斥。账号、范围或快照变化后，详情不能继续显示已失效记录。

选择模式中点课程继续切换勾选，不为详情面板改变单击含义。若未来需要选择时看详情，应另行设计明确的详情入口，不增加未告知的长按手势。
