## 3. 设计选择

| 决策 | 采用方案 | 取舍依据 |
| --- | --- | --- |
| 学分来源 | 成绩提供通过事实；用户填写目标 | 当前没有经过核实的培养方案/学分认定接口，不能展示推测的学校毕业要求 |
| 学分计算 | 新建独立规则，不改现有算分口径 | 现有统计学分包含不及格和重复考试记录，适合均分分母，不等于完成学分 |
| 备份格式 | 显式白名单数据、版本化清单、归档文件 | 裸数据库和 DataStore 文件含设备标识及会话关联，不适合直接迁移 |
| 云端行为 | 用户主动备份和恢复，每次保存独立版本 | 本期不做后台定时上传或双向实时同步，避免把文件备份扩展为冲突合并系统 |
| 首页配置 | 专用编辑页、预览、保存/取消 | 调整布局时可检查结果，且不会因半途返回保存一半 |
| 源码复用 | 可兼容代码直接移植；学校规则和框架代码按职责改造 | 保留来源和许可，实际移植时列明修改范围，不为复用小段代码引入整套框架 |

上述取舍是本计划的建议范围。用户尚未授权本组计划开始实施。

## 5. 实施顺序与依赖

1. 先固定学分目标、首页配置与备份白名单的字段职责和默认值，避免后做的备份漏掉新设置。
2. 实现学分进度：规则、账号隔离、完整性标记、页面及入口。
3. 实现首页增强：配置、路由、课程时间投影、前台刷新与交互。
4. 实现统一本地备份和恢复；先验证本地完整闭环，再接 WebDAV。
5. 接入 WebDAV 独立版本、列表与恢复，完成失败路径和恢复中断测试。
6. 独立审查三项接合处：账号/标识映射、设置覆盖、恢复后的外部副作用、导航与退出状态。
7. 运行对应自动化检查和 Debug 构建；安装和真实数据/服务器验收另行记录。

开发时可以并行处理独立规则和页面，但共享的 Settings、DataStore、主导航、DI 和备份协议应由同一集成负责人协调。不得同时覆盖这些文件。
